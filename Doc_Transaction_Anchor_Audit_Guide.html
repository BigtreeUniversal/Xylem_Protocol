3. Base Ethereum Layer-2 Contract Audit

Every daily state root (H_day), alongside its parent hash and branch metadata, is committed immutably onto an Ethereum Base Layer-2 smart contract.

CRITICAL REQUIREMENT: DAY + 1 (J+1)

Daily state aggregation, Merkle sealing, and L2 contract commits occur automatically post-00:00 UTC. Therefore, you must query the contract events for Day + 1 (J+1) relative to your transaction's timestamp to locate the finalized settlement payload[.

To inspect the on-chain record on the Base network:

  1. Navigate to the official Base Layer-2 contract explorer page.
  2. Locate the target date transaction block (J+1).
  3. Pro-Tip: Switch the event data view to UTF-8 mode on the contract page to instantly decode and extract the 24 hourly IPFS CIDs, the daily Merkle Root (H_day), and the parent hash link.

4. Nostr Relay Network & Bitcoin OTS Verification

Beyond Layer-2 settlement, the astronomical oracle stream is anchored directly to the Bitcoin L1 network using OpenTimestamps (.ots). Daily .ots proofs are encrypted on-the-fly and broadcasted as decentralized Nostr events.

Step-by-Step Nostr Audit Protocol

  1. Fetch the target event from the Nostr network corresponding to J+1.
  2. Copy either the raw Event ID or the complete JSON event payload from the relay broadcast.
  3. Paste the payload into the dedicated decoder module available within the Oracle Verification Console.
  4. Download the reconstituted 24 hourly .ots proof files and their associated IPFS images.
  5. Submit the .ots files to the official OpenTimestamps verifier to mathematically validate the Bitcoin block height timestamp.

5. Essential Timestamp & Synchronization Safeguards

Prevention of Date Mismatches

Every astronomical image payload embeds its precise creation date formatted in Unix epoch time within its filename. Because Nostr relays cache historical events asynchronously, querying the network can occasionally yield out-of-order records.

  • Always verify that the Unix timestamp embedded in the .jpg filename matches the corresponding .ots proof file.
  • If a relay mismatch occurs, hard-refresh your browser page to pull the latest published state from the Nostr event stream.
  • Use the built-in Unix/UTC converter on the Oracle Console to cross-reference timestamps instantly.
